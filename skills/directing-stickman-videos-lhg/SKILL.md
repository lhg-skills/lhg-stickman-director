# 火柴人视频导演（lhg 版）

## 方法

完整实现仓库根目录 `METHOD.md`。执行顺序严格按其第 1–7 节推进，
不得跳过 Setup gate 与确认门。上游原版文件（`../directing-stickman-videos/`）
仅作风格配方与样例参考，不直接执行。

开工前先看 `styles/` 下是否已有对应画风的风格卡；有则**直接沿用其人物锚点、
环境、负约束、配音参数**，不重新发明（跨片一致性）。

## 执行层（相对上游的替换）

上游执行层 = Gemini Omni Flash via Google Flow 单链路。
本版双执行层，按路由规则选用：

### A. Muse 直出层（默认先行）

- **分镜预览图**：Muse Image，按分镜表每镜出一张预览图（画幅与成片一致），
  用于确认风格配方与构图，不烧 Flow credits。
- **草稿视频**：Muse Video，每镜一条约 10 秒。每轮上限 6 条：
  N ≤ 6 一轮跑完；N > 6 按 6 条一批分轮，批与批之间用上一批尾镜 snapshot 承接。
  prompt 用英文画面描述（人物 DNA 锚点逐字 + 环境 + 三节拍动作 + 负约束），
  音乐只描述情绪（如 quiet piano, upbeat electronic），不指定音频文件。
  需要视觉延续时用 snapshot 引用上一镜。
- **中文配音**：Muse TTS，按分镜切分旁白文本逐段生成；
  同一视频同一音色/语速/语气参数（声音连续锁的中文实现）。
- **用途**：验证分镜、节奏、风格；简单风格可直接成片。

### B. Flow 质量层（Gemini PRO）

- **对象**：Muse 草稿中"必须高质量"的镜头（人物特写、复杂运镜、关键转场），
  默认不整片重做。
- **prompt**：沿用 METHOD.md §5 的 12 步结构，但做"音轨剥离"改写（见下节）。
- **预算纪律**：每月 1000 credits 内；Fast 档先过，Quality 档定稿；
  每天 50 免费分优先用于验证性生成。

### C. 音轨归属（双执行层的声音连续锁）

两层混用时，如果视频模型各自生成配音，同一支片会出现两种声音，违反 METHOD.md §6。
因此：

- **人声只有一个来源：Muse TTS。** 所有视频片段（Muse 与 Flow）均不生成旁白。
  Flow 版 prompt 第 8 步写 `No dialogue, no voiceover, no lip-sync`，第 9 步省略。
- **BGM 只有一条：后期统一铺。** 视频 prompt 第 10 步只保留物理动作的同步 SFX，
  不要求模型生成 BGM；合成时视频原声仅保留 SFX（或整体静音）。
- 旁白文字仍按批准版一字不差，只是从"写进视频 prompt"改为"交给 TTS"。

### D. 音画对齐

每段 TTS 生成后先测时长（`ffprobe`），再决定处理方式：

| TTS 时长 | 处理 |
|---|---|
| ≤ 9.8s | 直接用，尾部留白 |
| 9.8–10.5s | `atempo` 提速 ≤ 1.05，或视频尾帧延长 ≤ 0.5s |
| > 10.5s | **停下来**：列出超时段落和删减建议，等 lhg 批准新台词（改台词属于"改镜"） |

不得为了对齐私自改台词，也不得把语速拉到 1.05 以上（听感会变）。

### 路由规则

1. Phase B 输出"双版提示词"：Muse 版 + Flow 版（同一分镜，两套提交格式，
   均已做音轨剥离），另附 TTS 分段文本与拼接指南。
2. 先跑 TTS 并测时长 → 按 D 节对齐（需要改台词就回确认门）。
3. 跑 Muse 全片草稿（图片预览 → N 条视频）→ 用户看片确认。
4. 标记需 Flow 重做的镜头（用户指定，或 Muse 版明显不达标）；无标记则不进 Flow。
5. FFmpeg/剪映合成：画面 + TTS 配音 + 字幕（旁白烧入）+ 一条 BGM + SFX。
6. 验收按 METHOD.md §7 清单；技术通过≠审美验收。

> TTS 提前到视频之前：时长是硬约束，先锁音频再出画面，避免草稿片白烧。

## 工作流

1. **Setup gate**：收齐素材/画幅/时长/画风。默认 9:16、60 秒、Style 1，
   仍需用户一次确认，不静默默认。若 `styles/` 已有风格卡，提示可沿用。
2. **建档**：在 `runs/YYYY-MM-DD-<slug>/` 建本次运行目录（结构见 `runs/README.md`），
   之后每个阶段的产出都落盘，交接 Agent 从这里续跑。
3. **Phase A**：中文导演提案 —— 中文旁白（45–55 字/10 秒）+ 英文对照版；
   五阶段心跳引擎；N 行分镜表（含三节拍、衔接命名、BGM/SFX）→ `proposal.md`。
4. **确认门**：批准 / 改镜 / 改全局（三选一）。批准结论写入 `log.md`。
5. **Phase B**：双版提示词包 + TTS 文本 + 拼接指南 → `prompts-muse.md`、
   `prompts-flow.md`、`tts.md`、`assembly.md`。
6. **执行**：TTS + 对齐 → Muse 草稿 → 看片确认 → Flow 补镜（按需）→ 合成。
   每次生成、每笔 credits 消耗记入 `log.md`。
7. **验收**：METHOD.md §7，结果写入 `log.md`。
8. **沉淀**：成片通过后，用 `styles/STYLE-CARD-TEMPLATE.md` 生成或更新风格卡，
   并在 `log.md` 写"下次要改的 3 件事"。

## 人机分工

- Muse：提案、提示词、生成、合成全包；每个 Flow 补镜先报预算（credits 估算），
  用户确认后再烧。
- lhg：Phase A 拍板；看草稿片拍板；Flow 补镜清单与预算拍板；超时台词删改拍板。
- 付费操作（Flow credits 消耗）必须先报预算后执行；不自动购买 credits。
  不可逆操作（删除已生成素材、覆盖风格卡）先确认。
